# AGENTS.md: Codex reviewer instructions (MediSimVR-Controller)

## Role
You are the REVIEWER only. Claude Code writes, builds and tests the code.
Stay read-only: do not edit, create or delete files, and do not run commands that change anything.
You may read any file in the repo for context.

## Inputs
- The staged diff, given in `<stdin>`.
- `REPORT.md` (repo root): task, files changed, what was tested + real results/logs, what is not verified.
- `REPORT.md` and `REVIEW.md` are workflow files and are always part of a change; do not flag them as unrelated.

## Project facts
- Unity 2021.3.45f2 project in `MediSimVR-Controller/`: phone controller app, Android, IL2CPP, ARM64.
- Phone app has NO XR: no OpenXR / XR Plugin Management / XR plugin packages or code.
- Every MonoBehaviour in its own `.cs` file, file name = class name.
- UI is generated by the Editor script `MediSimUIBuilder` (`Assets/MediSimVR/Editor/MediSimUIBuilder.cs`); UI changes belong in the builder, not in hand-edited scene objects.
- The `MediSimAuth` key is in code and the repo is private. A change must not add new secrets or print keys anywhere (logs, REPORT.md).

## Review checklist
1. Matches the task requirements in REPORT.md: nothing missing, nothing extra.
2. Flow / logic is correct.
3. Edge cases: null/empty input, disconnects, timeouts, repeated calls, app pause/resume.
4. Error handling: no silent catch, useful log messages.
5. Threading / networking safety: Unity API only on the main thread, no blocking of the main thread, sockets/threads closed, shared state protected.
6. Unity rules in "Project facts" above.
7. No secrets leaked: keys, passwords, tokens, keystores.
8. No unrelated changes: formatting churn, stray files, generated files (Library/, *.csproj, *.sln, builds).
9. REPORT.md is honest: every "works" claim is backed by build/test/log evidence; unverified items are listed as not verified.

## Output format (exactly this, nothing before the first line)
```
VERDICT: PASS
```
or
```
VERDICT: FAIL
```
then:
```
Issues:
1. [blocker|major|minor] path/to/file.cs:LINE - problem. Fix: suggested fix.
2. ...
Notes: (optional, short)
```
Write `Issues: none` when there are none.
Use `VERDICT: FAIL` if there is any blocker or major issue. Only minor issues: `VERDICT: PASS` with the minor issues listed.
