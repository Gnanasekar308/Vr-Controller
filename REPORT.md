## Task
M2: phone "Scene" tab (Live Scene).
- Bottom nav: Home, Devices, Send, Control, Scene, Settings. Screen title "Live Scene".
- 3D view: SyncWorld (floor + 1 m grid, cube, light, camera) far from the UI, rendered to a RenderTexture shown in a RawImage; main camera cullingMask = 0; the 3D camera renders only while the tab is visible.
- Move / Rotate / Scale modes + pinch (scale, all modes) / twist (spin, Rotate mode); mouse in the Editor.
- Save / Load / Reset with `cube_state.json` (persistentDataPath, format `{"app","version":1,"savedAt","position","rotationEuler","scale"}`).
- SceneSync protocol files copied from the receiver project so both sides are identical (same key as the MediSimAuth key).
- Multi-target: every receiver answering "here" (kind pc / quest) is kept; each transform goes to all. Status chip lists all connected names. Manual IP field accepts several IPs (comma separated, saved in PlayerPrefs).
- First "here" with a cube state (before the user touched the cube) is adopted by the phone and then sent to all.

## Review rounds
- Round 1: VERDICT: FAIL, 2 major:
  1. `SceneSyncClient` receive thread swallowed socket / general exceptions. Fixed: rate-limited warning (1 per 5 s, with total count and message) via `RxError`.
  2. `EnsureTexture` could run before layout (zero rect -> 64x64 texture, never resized). On the phone the log showed the real size (1178x1131), but fixed anyway: a zero-size rect is skipped, and `Update()` calls `EnsureTexture()` every frame (returns early if the size is unchanged, recreates the texture if the view was resized).
  Re-test after the fix: `batch_apk2.log` `Build Finished, Result: Success.`; `adb install -r` Success; Scene tab opened + 1-finger drag: logcat `Scene view RenderTexture 1178x1131` (logged once, no re-creation loop), `SceneSync client on UDP 34250, discover to ...`, no exceptions.
- Round 2: VERDICT: FAIL, 2 major: `SyncReceiver` called `Debug.LogWarning` on its UDP thread (socket errors, `Drop()`).
  Fixed (in both `SceneSync` copies, still identical, and in `SceneSyncClient`): the network threads now use no Unity API at all:
  - log lines go into a `ConcurrentQueue<string>` (max 100) and are written by `Update()` / `Tick()` on the main thread;
  - the threads only check the signature (`SceneSyncProtocol.TryVerify`, pure .NET) and queue the verified body (max 256);
    JSON parsing (`JsonUtility`) moved to the main thread via the new `SceneSyncProtocol.TryParseBody` (`TryParse` = TryVerify + TryParseBody, kept for the self test).
  Re-test after the fix:
  - Receiver project batchmode `SceneSyncSelfTest.Run` (same SceneSync files): 11 checks `[MSVR-TEST] PASS ...`, `[MSVR-TEST] ALL PASSED`, exit 0.
  - Phone `batch_apk3.log`: `Build Finished, Result: Success.`; `adb install -r` Success.
  - Fake-receiver test again on the phone: `SceneSync dropped packet from 127.0.0.1:35394: bad or missing sig`, `found PC-TEST (pc) ... receivers now 1`, `adopted cube state from PC-TEST: pos (0.200, 0.800, -0.300) rot (0.0, 45.0, 0.0) scale (0.700, 0.700, 0.700)`, `found Quest-TEST (quest) ... receivers now 2`, transforms received: pc 8, quest 8, bad-sig sender 0; then `lost PC-TEST`, `lost Quest-TEST`. No exceptions.
