## Unity rules
- Unity 2021.3.45f2 only.
- Phone app has NO XR: never add OpenXR / XR Plugin Management / any XR plugin to this project.
- Every MonoBehaviour in its own file, file name = class name.
- UI is generated by `MediSimUIBuilder` (`MediSimVR > Build UI Scene`): change the builder, not hand-edited scene objects.
- Never print the `MediSimAuth` key in logs, REPORT.md or chat.

## Work style
- Explain steps briefly in Tanglish. Inspect first, give a short plan, wait for the user's OK before changing anything.
- Tell the user before a step needs hardware ("connect the phone now").

## Work loop (EVERY task)
1. Do the task, build, test. Device involved: capture `adb logcat` evidence.
2. Write `REPORT.md` (overwrite): Task, Files changed, Tested + real results/logs, Not verified, Review rounds.
3. Review with Codex, **read-only**, from the repo root (Bash):
   ```bash
   git add -A
   git diff --cached -- . ':(exclude)REVIEW.md' | codex exec -s read-only --ephemeral -o REVIEW.md "Act as the reviewer defined in AGENTS.md. The staged diff is in <stdin>; the task and test evidence are in REPORT.md. Review with the AGENTS.md checklist and answer only in the AGENTS.md output format."
   ```
4. `VERDICT: FAIL`: fix the issues, update REPORT.md, review again. Maximum 3 rounds.
5. `VERDICT: PASS`: commit (REPORT.md + REVIEW.md included) and `git push`.
   Still FAIL after round 3: do NOT commit/push; stop and show the user the open issues.
- Codex stays read-only: never use `workspace-write`, `danger-full-access`, `--full-auto` or `--dangerously-bypass-*`.
- Never mark something as working without build/test/log evidence; list what is not verified.
